# Evergreen Dashboard

Персональный информационный дашборд. В одном экране собираются дата и местное время, погода, события Google Calendar, лента AI-новостей, ежедневные рутины и рабочий таймер. Состав, порядок и размер виджетов настраиваются. Уведомления уходят в браузер и в Telegram.

Вход — через Google. Календарь и Telegram подключаются отдельно. У пользователя есть доступ только к своим данным. Гость открывает страницу входа, политику конфиденциальности и условия использования.

Интерфейс адаптивный: на компьютере — боковая навигация и сетка виджетов, на телефоне — нижняя навигация. Есть светлая и тёмная темы.

Сейчас виджеты, рутины и таймер в браузере живут локально. HTTP API, вход через Google, очередь задач и worker уже есть и работают с PostgreSQL.

## Состав

Monorepo на npm workspaces. Команды ниже запускаются из каталога `my-app`.

| Путь | Что это |
| --- | --- |
| `apps/web` | Интерфейс на Next.js. В разработке слушает порт 3000. |
| `apps/api` | REST API на Express, префикс `/api/v1`, порт 4000. Тот же пакет запускает worker. |
| `packages/contracts` | Общие схемы и типы ответов API. |
| `packages/config` | Общие настройки TypeScript и ESLint. |
| `infra` | Локальный PostgreSQL и конфигурация развёртывания. |

Три процесса: `web`, `api` и `worker`. База — PostgreSQL 18, доступ к ней только у API и worker через Prisma.

## Требования

- Node.js 24 (`>=24.0.0 <25`)
- npm 11 (`>=11.0.0`)
- Docker, чтобы поднять локальный PostgreSQL

Стек и версии — в [документе технологий](./docs/TECHNOLOGIES.md).

## Запуск интерфейса

Этого достаточно, чтобы открыть дашборд в браузере. База и ключи Google не нужны: данные виджетов сохраняются в браузере.

```bash
cd my-app
npm ci
npm run dev:web
```

Откройте [http://localhost:3000](http://localhost:3000). Страница входа — `/login`, дашборд — `/dashboard`.

## Запуск целиком

Поднимает PostgreSQL, накатывает схему и запускает web, API и worker.

1. Установить зависимости: `npm ci`.
2. Заполнить корневой `.env` (см. ниже).
3. Для локального PostgreSQL запустить `npm run infra:up`. При использовании Neon этот шаг пропустить.
4. Применить миграции: `npm run db:migrate --workspace @dashboard/api`.
5. Запустить процессы: `npm run dev`.

Интерфейс — [http://localhost:3000](http://localhost:3000). API — [http://localhost:4000](http://localhost:4000).

Остановить базу: `npm run infra:down`. Логи контейнеров: `npm run infra:logs`.

В том же compose описан второй контейнер базы. Текущие API и worker к нему не подключаются.

### Файл окружения

`.env` не коммитится. Prisma, API и worker читают единый корневой файл. Значения,
переданные хостингом через переменные окружения, имеют приоритет.

Без четырёх значений API не стартует:

- `SESSION_SECRET` — не короче 32 символов, без пробелов;
- `DATA_ENCRYPTION_KEY` — 32 байта в hex (64 символа) или base64;
- `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` — клиент OAuth из Google Cloud. В консоли Google укажите значение `GOOGLE_REDIRECT_URI` из `.env`.

Сгенерировать локальные секреты:

```bash
npm run env:secrets
```

Команда заполняет только отсутствующие или некорректные значения и не выводит сами секреты.

Telegram, Web Push и ключ новостей можно оставить пустыми: без них соответствующие уведомления просто не отправляются. Погода ходит в Open-Meteo, отдельный ключ не нужен.
