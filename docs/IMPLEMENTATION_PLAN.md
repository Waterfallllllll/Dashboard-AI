1. Frontend — подготовить дизайн-токены, адаптивный shell, маршруты, светлую и тёмную темы.
2. Frontend — реализовать страницы входа, профиля, интеграций, рутин и юридических документов.
3. Frontend — собрать адаптивную сетку дашборда и независимые состояния загрузки, ошибки, пустых и устаревших данных для виджетов.
4. Frontend — реализовать виджеты даты и времени, погоды, календаря, рутин, таймера и AI-новостей на мок-данных.
5. Frontend — добавить редактор порядка, видимости, размера и параметров виджетов с drag-and-drop и клавиатурным управлением.
6. Frontend — реализовать CRUD-интерфейс рутин, управление таймером, геолокацией, разрешениями и уведомлениями.
7. Frontend — настроить PWA, service worker, Web Push, адаптивность, доступность, E2E-сценарии и контроль производительности.
8. База данных — поднять PostgreSQL 18 локально и в CI, подключить Prisma ORM 7.10.1 (`schema.prisma`, один клиент на процесс, `DATABASE_URL`) и описать модели пользователей, сессий, виджетов, рутин, таймеров, интеграций, новостей, очереди и уведомлений.
9. База данных — применить версионированную миграцию Prisma Migrate со внешними ключами, unique, partial unique и query-индексами, полями шифрования credentials и мягким удалением.
10. База данных — проверить планы запросов через `EXPLAIN`, целостность связей, очистку аккаунта и сроки хранения. Просроченные строки удаляет worker: у PostgreSQL нет TTL-индексов.
11. Backend — определить общие DTO, схемы валидации и единый формат API-ошибок. Репозитории читают и пишут данные только через Prisma Client.
12. Backend — реализовать Express API, Google OAuth, серверные сессии, профиль и разграничение доступа к данным пользователей.
13. Backend — реализовать модули настроек виджетов, рутин, таймеров и агрегированного дашборда.
14. Backend — подключить адаптеры погоды, AI-новостей, Google Calendar и Telegram с кэшированием и защитой от сбоев.
15. Backend — добавить worker, очередь в PostgreSQL (`FOR UPDATE SKIP LOCKED`), Web Push и Telegram-уведомления, webhook, retries, идемпотентность, очистку просроченных данных и мониторинг.
16. Backend — покрыть бизнес-логику unit- и integration-тестами на реальном PostgreSQL, выполнить E2E-проверки и security hardening.
